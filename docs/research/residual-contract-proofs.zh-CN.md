## 一、有限模型（`model.rs`）

### 1.1 身份、根契约与世界

- 身份 `Id` 至多 3 个，消费域 `Dom` 至多 2 个，观察槽至多 3 个，私密变量至多 8 个。
- 根契约 `Root`：
  - 每个域 d：总预算 b_d、资格集合 E_d；
  - 操作模板 o ↦ (所属域 dom(o)，是否产生公开回执)；
  - 声明观察槽 s ↦ (身份 who(s)，视图函数 view(s)，接收者)。视图函数有三种：
    该身份的秘密位 `Secret`、该身份在域 d 是否有活条目 `Live(d)`、域 d 中成功执行数 `SuccCount(d)`；
  - 目标项 (d, g)：域 d 中至少 g 个成功执行；
  - `vary_exists[d]`：域 d 中存在哪些身份是否属于私密世界。
- 世界 `World` = (每个身份的秘密位，每个域中存在的身份集合)。`Root::worlds()` 枚举与公开输入一致的全部世界：
  秘密位取遍所有组合；`vary_exists[d]` 为真的域，存在集合取遍所有子集（动态资源），否则固定为全部身份。
  世界在一次运行内不变。
- 环境不属于世界：执行结果、结果到达的时刻、替换窗口内的崩溃，都由探索器非确定选择。

### 1.2 受限语言

| 语句 | 含义 |
| --- | --- |
| `Discover(d) → L` | L := 世界中域 d 存在的身份（私密列表，按编号排序） |
| `Select(L, keep) → L'` | 保留秘密位等于 keep 的身份 |
| `ForEachBounded(k, L, x, body)` | 依次把 L 的前 k 个身份绑定到 x 并执行 body |
| `If(Secret(x) 或 NonEmpty(L), then, else)` | 按私密值分支 |
| `Attempt(o, x) → h` | 只经可信 `try_reserve(dom(o), x)`。成功则派发一个执行，把它的稳定 `ExecId` 存入 h；被拒则 h := 无执行 |
| `Await(h)` | 等待 h 所绑定的执行返回，并消费其结果一次；h 无执行时为空操作 |
| `Pin(s)` | 冻结槽 s 的当前视图值，不产生公开事件（本文新增，见 §5.5） |
| `OfferObservation(s)` | 若未冻结则先冻结，再释放冻结字节，产生公开事件 |
| `DirectEffect(o, x) → h` | 不属于受限语言：不经 `try_reserve` 的效果。只为检验 K2 而存在于语法树中 |

程序编译成带跳转的指令表（`compile`）。顶层第 i 条语句的起点就是切点 i；切点只取顶层语句边界。
文中程序写法与测试输出一致：`v0:=Disc(d0)`、`for2 v2 in v0 {...}`、`v3:=Att(o0,v2)`、`Await(v3)`、
`Offer(s0)`、`DIRECT(...)`；`skip` 表示空程序。

### 1.3 状态

- 效果存储 `Store`：
  - 账本：每域每身份一个条目，取值 `Reserved | Spent | ReleasedNoEffect | Indeterminate`。
    used(d) 为 `Reserved`、`Spent`、`Indeterminate` 条目数，称为活条目；
  - 执行表：每个执行有稳定 `ExecId`、操作、域、身份、状态 `Pending | Succeeded | FailedNoEffect | Unknown`、
    被 `Await` 消费的次数、是否经过预约；
  - 观察槽：冻结值（可空）与释放次数。
- 运行时状态 `Rt`：程序位置、变量（列表、身份、执行句柄）、循环游标、效果存储、下一个 `ExecId`。
- 组合系统配置 `Sys` = (世界, `rt`, `truth`, 公开历史, 替换阶段, 是否已判定, 崩溃次数, 违规标记)：
  - `rt.store` 是解释器看到并据以执行的状态；
  - `truth` 是外部真实发生的记录。

  完整设计中二者始终一致（引理 L0）。弱化契约可能在切换时交给解释器一个有损状态；全检查器按 `truth` 判定，
  损失于是表现为具体违规。
- 任务监控：目标项进度就是 `truth` 账本中各域 `Spent` 条目的个数。

### 1.4 小步语义

- 程序步（给定世界时是确定的）按指令执行。
  - `Attempt` 唯一的入口是 `try_reserve`：一次原子地判断资格、成员关系（该身份在该域没有活条目）与剩余额度。
    成功时只写一个 `Reserved` 条目，即扣一份额度；被拒时什么都不改。它只返回一个布尔值，不返回余额或成员集合。
  - 有回执的操作产生 `Attempted(o)` 或 `AttemptRefused(o)`，不含身份。
- 环境步：任一 `Pending` 执行可在任意时刻返回三种结果之一，包括迟到结果。结果同时写入执行表与账本：
  - `Succeeded → Spent`；
  - `FailedNoEffect → ReleasedNoEffect`：只有确认无效果才退回额度；
  - `Unknown → Indeterminate`：永不退回。
- 替换协议的四个阶段：
  1. `Old`：运行旧程序。第一次到达切点时，若公开历史等于提议所绑定的前缀 π，进入 `Deciding`；
     否则记为已判定，继续旧程序；
  2. `Deciding`：运行时执行检查；接受则进入 `Accepted`，否则回到 `Old`；
  3. `Accepted`：这期间可以有迟到结果，也可以崩溃（至多一次），恢复后回到 `Deciding` 重新检查。
     写切换记录这一步先按当时状态重验，通过则原子地安装候选，进入 `New`，否则回到 `Old`；
  4. `New`：运行候选；结束时产生 `Completed`。
- 公开事件只有 `Attempted(o)`、`AttemptRefused(o)`、`Observed(s, v)`、`Completed`。不可信规划器只看到它们。

### 1.5 全局性质（参照全检查器 `full.rs` 直接检查）

对组合系统，从每个世界出发、对每种环境调度穷举：

- P1 根授权：每个执行都经过预约；每个账本条目的身份有资格；每域 used ≤ b_d。
- P2 单调消费：同一身份同一域不出现第二个活条目；条目不删除；`Indeterminate` 不退回。
- P3 历史义务：每个执行的结果恰好被消费一次；`ExecId` 不重用（不换身份）；
  冻结的观察恰好释放一次，字节不变；已用过的槽不能再冻结（新快照即新观察）。
- P4 逐前缀披露（可能性语义）：记 Next(w, p) 为世界 w 在某种调度下产生前缀 p 之后可能出现的下一事件形状集合，
  其中 `Observed(s, v)` 的形状是 `Observed(s)`。对任意两个世界及它们都能产生的前缀 p，要求 Next 相等：
  声明槽的内容可以不同，其余公开行为（包括槽是否出现）不能依赖私密世界。
- P5 进展：没有"未终止又无后继"的配置（"每个未决执行最终返回"已体现为返回步总是可用）；
  成功环境（每个执行都立即返回 `Succeeded`、无崩溃）下，从每个判定点出发，组合系统达到旧程序剩余部分
  能达到的每个目标项。

全检查器不读残余契约。被测设计的判定与重建钩子在它运行的组合系统里，但判断对错只看组合轨迹。
为了速度，有界检查用"共享切点前探索、再从切点处每个配置继续"的分解形式（`full_check_from`）。
每个案例的第一个被接受候选、以及全部手写全检查测试，都与直接形式（`full_check`）比对，结果一致。

## 二、构造 C1–C6（`residual.rs`）

`build_contract(opts, root, old, cut, π, interface)` 只接收公开输入。`bind(contract, state)` 是唯一读取真实私密状态的地方。
`residualize(root, old, cut, interface, state)` 就是这两步的组合，契约部分只用 `state` 的公开历史。
测试 `contract_lists_pending_obligation_and_budget_parameter` 断言：私密状态不同、公开历史相同时，契约相等，绑定不同。

| 步骤 | 实现 |
| --- | --- |
| C1 足迹 | 旧程序剩余部分读写的域、操作、槽（含槽视图读取的域）、被等待的句柄、读写的变量、控制变量（循环列表、分支条件、`Select` 的来源） |
| C2 依赖闭包 | 足迹 ∪ 接口；加入接口操作所在的域；"槽视图读取的域"与"读取闭包内某域的槽"互相闭合，直到不动点；闭包域内的全部操作（共享预算）；不跟踪别名，闭包域的整行账本都保留；闭包域上的目标项 |
| 状态集合 S | 对每个世界、每种环境调度（含切点之前任意时刻到达的结果），运行旧程序到切点，取公开历史等于 π 的全部配置，投影后得到 S。这只用公开输入：枚举的是假想世界，不是真实世界 |
| C3 残余义务 | 仍未被消费的执行句柄（在 S 的全部或部分状态中）；已冻结未释放的槽；未完成的目标项。若某个未消费执行不能经任何闭包变量访问，契约为 Unknown |
| C4 历史绑定 | 可能持有执行的句柄变量（只引用，不重建 `ExecId`）；可能已冻结的槽；从 π 读出的已释放槽及其字节 |
| C5 参数化 | 每个闭包域的剩余额度在 S 上的取值范围。成员关系不写成清单，留在绑定所含的账本里，只经 `try_reserve` 使用 |
| C6 关系接口 | S 本身；S 是否对迟到结果封闭（`env_closed`）；旧剩余部分从 S 出发是否逐前缀安全（拒绝分支）；每个状态下旧剩余部分在成功环境中达到的目标项 |

C6 的字段省略：

- 只可能省略闭包外域的账本行与闭包外的槽；
- 省略前须通过有限探针检查：投影相同的两个完整状态，在每个接口单步（每个接口操作对每个身份的 `try_reserve`、
  每个接口槽的视图、每个接口变量）上结果相同；不通过就不省略；
- 变量从不省略。原因见 §5.5 第 17 条：静态 K2 允许候选在分支之后读取只在一个分支里赋值的变量，读到的是旧值。
  最初的实现会省略闭包外的变量，推理时发现了这个缺口并改正。

完整性校验：

- 契约的 digest 由内核在自己构造时计算一次；
- K1 对提议中的契约重新计算 digest 再比较，不信任契约自带的字段；
- 绑定 `LocalResidualBinding` = (元数据，真实状态的投影，内核自己算的 digest)，只存在于可信边界内。

## 三、检查 K1–K6（`check.rs`）

检查分两步：

- `prepare(cfg, contract, candidate)` 只读契约与候选（公开数据），在 S 的每个状态上做 K2–K6；
- `decide(cfg, contract, digest, prepared, binding)` 在此基础上只加 K1 绑定检查。

所以在完整设计下，判定 = K1 是否通过 + 一个只依赖公开数据的结论。`check_replacement(contract, binding, candidate)` 就是二者的组合。

| 检查 | 实现 |
| --- | --- |
| K1 绑定 | 根、语义版本、旧程序、切点、π、接口、构造选项逐项相等；提议契约重算的 digest 等于内核自己构造的 digest；绑定的投影状态属于 S。运行时在写切换记录前、以及崩溃恢复后的重新判定中都再做一次 |
| K2 单步安全 | 静态部分：只用受限语言（拒绝 `DirectEffect`）；只用接口内的域、操作、槽与历史变量；变量按种类使用；尝试的身份只来自候选自己的循环项。动态部分：从 S 的任何状态出发都没有非法步 |
| K3 义务守恒 | 从 S 的任何状态出发的任何运行中：旧执行与新执行都恰好消费一次；不重用 `ExecId`；冻结槽恰好释放一次且字节不变；已用槽不再冻结。新义务只能经接口操作的 `try_reserve` 产生（由 K2 保证） |
| K4 关系保持 | 新/新：同一世界里从全部 S 状态出发的候选 Next 先合并，再在任意两个世界的公共前缀上比较。拒绝分支（旧/旧）：要求旧剩余部分从 S 出发逐前缀安全。判定一致性：判定只读公开数据与 K1 |
| K5 恢复闭包 | S 对迟到结果封闭：任一未决执行以任一结果返回后，状态仍在 S 中；崩溃发生在切换记录之前时，恢复后重新判定。候选自身运行中的迟到结果由局部探索的异步语义覆盖 |
| K6 条件进展 | 从 S 的任何状态出发都没有卡死配置；成功环境下，对 S 的每个状态，旧剩余部分达到的闭包目标项，候选也达到。不引入更强的环境假设 |

以下情形结论为 Unknown：

- 切点不能静态对齐；
- 有不可寻址的未消费执行；
- 探索超出上限；
- 旧剩余部分本身不逐前缀安全。

运行时把 Unknown 当作拒绝。

## 四、证明

### 4.1 假设与引理

- A1 初态安全：旧程序单独运行时满足 P1–P5（参照全检查器通过）。
- A2 契约由内核自己构造：按完整选项、从公开输入构造契约 C；构造是穷举的，且包含任意时刻到达的结果；
  没有截断；`unknown` 为空。
- A3 切点公开对齐：切点之前每条顶层语句产生的公开事件数，与世界和调度无关。构造用静态计数检查这一点，
  不满足就是 Unknown。记该数为 L = |π|。
- A4 切换原子：写切换记录是一步，安装候选并保留内核的全部记录（账本、执行、槽、变量），即重建等于恒等。
- A5 故障模型：崩溃只发生在"接受"与"写切换记录"之间，次数有限，恢复后重新判定。其余每个小步都是原子提交，
  响应丢失由环境结果 `Unknown` 表示。
- A6 环境：结果可在任意时刻以三种之一到达；对每个未决执行，返回步总是可用。成功环境是每个执行立即返回
  `Succeeded`、没有崩溃。
- A7 运行时只在判定为 Accept 时切换；Reject 与 Unknown 都保留旧程序。

**引理 L0（运行时与真相一致）**：完整设计下，组合系统中任一无违规的可达配置满足
`rt.store = truth`，并且 `pre_used = 0`、`pre_obs = 0`。

证明。对步数归纳。初态两边都为空。

- 程序步：`try_reserve` 与真相账本在相等的存储上判断同样的资格、成员与余额条件（`pre_used = 0`），
  所以要么两边写同一条目，要么都不写；新执行同时加入两边；`Await` 在两边各加一次消费计数，计数超过一即为违规；
  冻结与释放在两边写同一个值。
- 环境步：两边做同样的更新。
- 切换（A4）：不改存储。∎

**引理 L1（覆盖）**：设 c 是组合系统中处于 `Deciding` 或 `Accepted` 的任一配置（任何世界、任何调度、
崩溃前后均可）。把 c 的阶段改回 `Old`，得到的是旧程序在切点、历史为 π 的可达配置。因而 proj(c) ∈ S，
且 c 的绑定通过 K1。

证明。组合系统在第一次到达切点之前与旧程序逐步相同，只有历史为 π 时才进入 `Deciding`。此后到写切换记录为止，
改变 (rt, truth, 历史) 的只有环境返回步，判定、重验失败与崩溃只改阶段字段，而返回步不产生公开事件。
构造 S 时探索器在切点上同样允许任意返回步（A2），所以这些配置都在构造所枚举的集合里。
元数据与 digest 相等由 A2 给出：诚实情形下提议的契约就是内核的契约。∎

K5 的 `env_closed` 是 L1 中"切点上的迟到结果"这一部分的可检查形式，但它不能单独替代 A2。
设构造只在 `Await` 时让结果返回：切点之前一个较早的 `FailedNoEffect` 会退回额度，改变后续 `try_reserve` 的结果，
这样到达切点的状态不是任何 S 状态的迟到结果后继。本实现中，由 K1 的 digest 比较保证提议契约就是内核按 A2 构造的契约。

**引理 L2（判定一致）**：在 A2 下，对历史为 π 的任一判定或重验配置 c，`decide` 的结果都等于
`prepare(C, Q).public`，只依赖 C 与候选 Q，二者都是公开的。若提议携带 C′ ≠ C，则对所有 c 都因 digest 不等被 K1 拒绝。

证明。由 L1，K1 对每个这样的 c 都通过；K1 通过后，`decide` 只返回公开结论。∎

**引理 L3（受限与投影）**：设 c 是切点处历史为 π 的无违规配置，σ = proj(c) ∈ S，候选 Q 通过静态 K2。记：

- c′：把 c 改成 `New` 阶段、程序位置 0，即 A4 下切换后的配置；
- s_σ：把 σ 展开成局部探索的起点，真相取为其运行时存储。

则从 c′ 与 s_σ 出发的运行在相同选择序列下一一对应。对应配置的公开历史、违规、是否终止或卡死都相同；
除被省略字段（闭包外域的账本行、闭包外的槽）和簿记字段（是否已判定、崩溃次数）外，配置完全相同。

证明。对步数归纳。

- 起点：投影只省略上述字段；由 L0，c 中的真相等于运行时存储。
- 程序步：由静态 K2，Q 只读写下列内容，所以每步的效果、公开事件与违规判定只依赖未省略字段：
  - 接口内的域（⊆ 闭包域）的账本行；
  - 接口内的槽（⊆ 闭包槽，其视图读取的域也在闭包内，见 C2 的不动点）；
  - 变量（从不省略）、世界（完整保留）、执行表（从不省略）与下一个 `ExecId`。

  唯一读取全部槽的程序检查是冻结时的观察计数检查。完整设计中 `pre_obs = 0`，被冻结的槽此前未冻结，该检查恒不触发。
- 环境步：两边的未决执行集合相同，所以可选的返回步相同。返回一个闭包外域的执行时，只有被省略的账本行在 c′ 一侧变化。
- 终止时的义务检查：它读取全部执行与全部槽。执行两边相同。若某个闭包外的槽在 c 中已冻结未释放，
  旧剩余部分（足迹在闭包内）永远不会释放它，旧程序就会在某次运行结束时违反 P3，与 A1 矛盾。
  所以两边对闭包外的槽都不会报错。
- `New` 阶段中，簿记字段不影响后继。∎

### 4.2 T1：接口相对的残余充分性

**命题**：在 A1–A4、A6 下，设 C 由公开输入 (R, P_old, i, π, I) 构造。

1. 覆盖：旧程序在切点、历史为 π 的每个可达配置 c，以及此后又到达迟到结果的配置，都满足 proj(c) ∈ S，
   其绑定通过 K1。
2. 接续：对任何通过静态 K2 的候选 Q，Q 从 c 的真实运行（内核保留全部记录，只经绑定接续真实状态）
   与 Q 从 proj(c) 出发的局部运行一一对应：公开事件、P1–P3 违规、终止与卡死都相同，成功环境下达到的闭包目标项相同。
   闭包外的目标项，Q 与旧剩余部分都不触及，其计数不变。
3. 因此在 S 上量化成立的每条性质，在真实接续上也成立。特别地，K2、K3、K6 在 S 上成立时，
   真实接续满足授权、单调消费、历史义务与条件进展。

T1 不声称"公开等价的状态剩余权限相同"，也不声称契约能恢复原始秘密。S 里不同状态的账本可以不同（如框架 §8.5 的 S1、S2），
差别留在绑定里，由 `try_reserve` 私下处理。成对状态关系不在 T1 内，由 K4 与 T2 处理。

**证明**：

- 第 1 条即 L1。
- 第 2 条由 L3（加 L0）得出。成功环境是一种特定调度，L3 的对应保持目标计数。闭包外目标项所在的域上，
  既没有 Q 的操作（K2），也没有旧剩余部分的操作（足迹在闭包内），只有切点前遗留执行的返回，两边相同。
- 第 3 条由 1、2 直接得出。∎

### 4.3 T2：关系式替换与恢复保持

**命题**：在 A1–A7 下，设提议 (Q, C′) 任意，可以是恶意的：任意语法树（包括受限语言之外的节点）、任意契约。
运行时用完整设计：K1–K6 如第三节；判定 = `decide`；写切换记录前重验；崩溃后重判；接受后重建为恒等。
则组合系统满足：

- P1、P2、P3、P4；
- P5 的两部分：没有卡死配置；成功环境下，从每个判定点出发达到旧剩余部分达到的目标项。

成功性只在成功环境下保证；其他环境下只保证收束（运行终止且义务全部消费）。T2 也不保证恶意规划器愿意提出有用的候选。

**证明**：由 L2，历史为 π 的所有配置判定相同。分两种情形。

**情形一：不接受**（包括 C′ ≠ C 被 K1 拒绝、受限语言之外的 Q 被 K2 拒绝、以及 Unknown）。
判定步只把"已判定"置真，`Accepted` 永不出现，组合系统的运行与旧程序完全相同。由 A1 得 P1–P5，P5 的目标比较中两边相同。

**情形二：接受**。此时 C′ = C：digest 相等。模型中 digest 是 64 位非密码学散列，这里假设无碰撞；
真实系统应使用密码学散列。并且 K2–K6 在 S 上成立。把每次运行分成三段：

1. 切点之前：与旧程序相同。由 A1，这段上 P1–P3 成立，也没有卡死配置。
2. 到达切点时历史 h ≠ π：不切换，此后与旧程序相同，由 A1 得 P1–P3、P5。
3. 到达切点时历史 = π：依次经过 `Deciding → Accepted`，期间可能有迟到结果，也可能崩溃后回到 `Deciding`。
   由 L1、L2，每次判定与重验都接受；崩溃次数与返回步都有限，所以最终写切换记录，从某个 proj(c′) ∈ S 的配置 c′ 开始运行 Q。
   - P1：Q 的每个效果都来自 `Attempt`（静态 K2 排除了 `DirectEffect`），经过 `try_reserve`。由 L0，
     `try_reserve` 在真相上判断同样的资格、成员与余额，所以每个执行都经预约、身份有资格、used ≤ b_d。
   - P2：由 L0 与 `try_reserve` 的原子判断，不会出现第二个活条目。语义上条目从不删除，返回步只改变 `Reserved` 条目，
     `Indeterminate` 不退回。
   - P3，以及 P5 中"没有卡死"的部分：由 K3、K2（动态）与 K6，从 S 的任何状态出发都没有义务违规、非法步或卡死；
     由 L3，从 c′ 出发的真实运行也没有。
   - P5 的目标部分：对每个判定配置 c，成功环境下的组合运行先让未决执行返回，再判定、切换、运行 Q；
     旧基线则让 c 留在旧程序。由 L3，二者的闭包目标计数分别等于从 proj(c) 出发的局部运行，
     以及契约中记录的旧剩余部分运行。K6 要求旧剩余部分达到的目标候选也达到；闭包外的目标项两边相同（T1 第 2 条）。

**P4**：取两个世界 w1、w2 都能产生的前缀 p。由 A3，每次运行在切点处的历史长度都是 L。分三种情况：

- |p| < L：任何运行中第 |p|+1 个事件都在切点之前产生，而这段与旧程序相同。所以 Next(w, p) 与旧程序相同，由 A1 相等。
- |p| ≥ L，且 p 的前 L 个事件 ≠ π：产生 p 的运行都没有切换，Next 与旧程序相同，由 A1 相等。
- p 的前 L 个事件 = π：产生 p 的运行都切换了（由 L2，且最终会写切换记录）。
  - 历史为 π 的配置，在切点之前、以及判定与接受阶段，都不再产生事件。所以 π 之后的事件都由 Q 产生，
    且 Q 从某个投影在 S_w 中的配置开始。
  - 反过来，S_w 的每个状态都是 w 中某个切点配置的投影；从这个配置可以不经迟到结果直接判定并切换。
  - 因此 Next(w, p) = ⋃_{σ∈S_w} Next_Q(σ, p)，其中用 L3 把真实配置换成了投影。
  - K4 要求的正是：这些并集在任意两个世界的公共前缀上相等。

所以组合系统满足 P1–P5。∎

**关于交叉对**：框架 K4 要求检查同一公开提议下的旧/旧、新/新、旧/新、新/旧以及拒绝分支。本实现中，
旧/新与新/旧两种混合对不会出现在同一公开前缀下：

- L2 说明判定只依赖公开数据；
- L1（以及作为其可检查部分的 K5 封闭性）说明，重验与崩溃后的重判不会因迟到结果改变结论；
- 拒绝分支由 A1 与契约中的"旧剩余部分逐前缀安全"覆盖。

测试 `necessity_each_safe_without_cross_pairs` 与 `k5_matters` 分别说明：去掉判定一致性，或去掉封闭性，
混合对确实出现并造成泄漏。

**多次替换**：把"旧程序"推广为"当前组合系统"Σ_k。它满足三条：

- 仍是同一配置空间上的有限迁移系统；
- 切点处的可达配置可以从公开输入（各段程序文本、各次切点与公开前缀）枚举；
- 由第 k−1 步保证满足 P1–P5，相当于 A1。

上面的证明只用到这三条，所以对有限次替换（中间可以夹迟到结果和替换窗口内的崩溃）归纳成立。
代码与有界检查都只做每次运行一次替换，多次替换只有这段纸面论证。

**事实更新**：本模型中的事实更新只有执行结果的到达；世界事实（存在集合、秘密位）在一次运行内固定。

### 4.4 T3：带条件的局部证明复用

设旧剩余部分是 A; B，候选是 A′; B（B 原样保留）。条件：

- (i) A′ 通过静态 K2；
- (ii) A′ 不写 B 读取的变量；
- (iii) A′ 不消费 B 负责消费的执行，即义务按句柄划分。

也就是说，B 与 A′ 只通过已检查的接口交互：共享域上的 `try_reserve`、槽、执行表。

**命题 3a（安全可局部复用）**：在 (i)–(iii) 下，B 的逐步安全义务在 A′ 之后的任何状态上仍然成立，
不需要重新探索 B。这些义务是：不出现非法步，授权（P1），单调消费（P2），B 自己创建的执行恰好消费一次（P3 中 B 的部分）。

证明。B 的语句不变。

- 由 (ii)，B 读取的变量的值与种类，与在 A 之后相同，所以 B 的步骤不会变成非法步。
- `try_reserve` 从任何状态出发都保持 P1、P2：只在资格、成员、余额都满足时才写一个条目。
- B 创建的执行有新的 `ExecId`，并由 B 自己的 `Await` 消费；由 (ii)(iii)，A′ 不碰这些句柄，也不提前消费 B 负责的旧执行。

这些论证都不依赖 A′ 留下的账本状态。∎

**命题 3b（完成性与关系性质不局部）**：B 能否完成它的那一步、B 的公开行为，都依赖共享状态，必须在依赖闭包上重新检查。

**共享预算反例，纸面形式**：

- 域 d 预算 2，有文件 F、G、H。A 归档 F，B 归档 G。
- A′ 改为归档 F 和 H，用完了预算。
- B 对 G 的尝试被 `try_reserve` 拒绝。B 的全部安全义务仍成立：没有超额，没有重复消费，没有丢掉的义务。
- 但"G 已归档"不再成立。

**共享预算反例，代码形式**（测试 `t3_shared_budget_keeps_safety_but_not_completion`）：

- R1 改为预算 1、目标 (d0, 1)。
- 旧程序 `[v0:=Disc(d0); v5:=Sel(v0,1); B]`，其中 B = `for1 v2 in v5 {v4:=Att(o0,v2); Await(v4)}`，
  即 B 归档第一个秘密位为 1 的文件。
- 候选 `[A′; B]`，A′ 归档第一个被发现的文件。
- K1–K6 全部通过，组合系统全检查通过（任务目标仍由 A′ 达成）。
- 但在"身份 0、1 都存在，只有身份 1 的秘密位为 1"的世界里，成功环境下：
  - A′ 归档身份 0，用掉唯一的额度；
  - B 对身份 1 的尝试因预算（而不是成员关系）被拒，句柄为"无执行"；
  - 旧程序中 B 本来成功。

本模型的目标项按域计数，所以这个例子中任务目标没有丢失。若 B 的那一步本身就是一个目标项，只在局部检查 A′ 的做法会漏掉它。

关系性质同样不局部。设 B 用带回执的操作，A′ 按秘密位决定是否消耗共享额度：

- A′ 单独看没有公开事件；
- B 单独看行为一致；
- 合起来，B 的回执泄露秘密位。

所以复用规则是：

- 可以复用：B 的逐步安全证明（K2、P1、P2、B 自己那部分 K3）；
- 必须在依赖闭包上重新检查：K4 与 K6，以及与 A′ 共享执行或槽时的 K3。C2 把共享域的全部操作、
  读取该域的槽都放进闭包，用的就是这条规则；
- 无法证明 (ii)(iii) 时，退回整体检查。

本实现没有证明缓存，每次都检查整个候选。T3 只说明今后哪些部分可以复用，不声称有加速。

### 4.5 必要性（框架 §5.5）

弱化契约的含义：切换后，解释器只拿到该契约与绑定所携带的内容（`apply_variant`），检查也只在相应的 S 上做。

| 弱化 | 丢掉的内容 | 后果与反例 |
| --- | --- | --- |
| 只传余额 | 成员关系 | 即 §8.5 的 S1/S2：余额相同，成员不同。只带余额时，切换后的账本不知道 F 已消费，会再次预约 F。默认搜索找到：R1，旧程序 `[v0:=Disc(d0); for2 v2 in v0 {v4:=Att(o0,v2); Await(v4)}]`，切点 2，候选 `[for1 v6 in v0 {v7:=Att(o0,v6); Await(v7)}]`；在"只存在身份 0"的世界出现 DoubleConsumption。完整设计接受同一候选，组合检查通过：成员关系留在账本里，由 `try_reserve` 私下拒绝 |
| 只传消费集合 | 执行状态与句柄 | 不知道哪些执行仍欠一次 `Await`，也不知道已用过哪些 `ExecId`。搜索在同一位置找到 ExecIdReuse：新执行重用了旧 `ExecId`，原执行的迟到结果无法归属原义务。手写测试 `consumption_set_only_drops_a_pending_obligation`：旧程序已发出 F 但未等待，候选不等待 F；弱化设计接受，全检查器报 ObligationDropped，完整设计以 K3 拒绝 |
| 只传观察次数 | 槽、冻结字节与函数 | 恢复时只能按最新数据重算。手写测试 `observation_count_only_recomputes_a_pinned_slot`：槽 s1（`Live(d0)`）在尝试之前冻结；在弱化设计下，连恒等替换都按最新账本重新冻结，全检查器报 ReObserved；完整设计接受同一恒等替换，组合检查通过。搜索还找到"重新提供已释放的槽"的反例 |
| 新旧各自安全（无交叉对） | 判定一致性 | 判定读真实私密状态，同一公开前缀下一边切换、一边不切换。搜索找到：R1，旧程序 `[v0:=Disc(d0)]`，切点 1，候选 `[for1 v6 in v0 {v7:=Att(o0,v6)}; Offer(s0)]`。发现列表为空的世界没有未消费义务，候选被接受；列表非空的世界被拒绝。空前缀之后的下一事件集合是 `{Observed(s0)}` 对 `{Completed}`，泄露了列表是否为空。完整设计以 K3 在全部 S 上拒绝。手写测试 `section_8_4_each_safe_but_secret_selected_switch_leaks` 是框架 §8.4 的原例 |

这些是本模型、本界限内的反例，说明每一部分在这里都不可省略。它们不是对一般系统的下界证明。
框架 §5.5 也指出，只有余额的系统可以靠全部拒绝来保持安全；这里展示的是，在同样接受这些候选的前提下，缺了哪一部分就会出错。

  - 等待历史句柄、等待新句柄；
  - 重新 `Discover`；
  - 每个操作的"循环一次 / 两次尝试并等待""按秘密位尝试""只发起不等待"；
  - 每个槽的 `Pin` 与 `Offer`；
  - 一个 `DirectEffect`。

### 5.3 没有说明的

- 有界不是参数化。检查只覆盖上表界限内的身份数、预算、程序长度与候选长度；更长的程序、更多身份或更大的预算，
  可能出现这里没有的反例。
- 证明对象是有限模型，不是 Rust 内核，也不是 `planning.rs`、`fused_planning.rs`、kerneld 的精化证明。
- 纸面证明没有机器检查。L0、L3 等引理依赖对代码的逐条阅读。
- 局部检查与全检查器共用 `model.rs` 的语义。语义本身若有错，两者会一起错（同源风险）。
  分解全检查与直接全检查的比对只覆盖全检查器自身的实现。
- 披露采用可能性语义，按世界比较，不覆盖概率、计时与资源侧信道；环境选择（结果、到达时间、崩溃）不当作秘密。
- 审批、期限、租约、撤销、pLLM、云端队列、提供方响应内容、双 owner 持久化与防回滚锚都不在模型里。

### 5.4 与框架 §5 文字的差异

- C1：`Await` 的足迹不包含被等待执行所在的域，因为它在静态上未知；作为补偿，执行表从不省略。
- C2：别名一律按整个域处理；存在集合作为世界的一部分完整保留。
- C3：
  - "收到响应"对应 `Await` 消费结果，"任务成功"对应目标计数，"安全结案"对应终止且义务消费完；
  - 已冻结的槽视为必须释放的观察义务。框架没有明说这一点，这里按保守处理。
- C5：没有符号参数化证明。S 显式列出与公开前缀一致的每种账本取值，检查在每个取值上运行可信 `try_reserve`；
  真实取值只在绑定里。这在有限模型中与参数化等价，但契约大小随状态数增长，不是压缩。
- C6：关系接口是显式集合 S 加上若干布尔量与表，不是关系公式。省略只限闭包外的账本行与槽。
- K1：digest 在模型里是 64 位非密码学散列。
- K4：
  - 不逐对比较旧/新、新/旧，而是证明它们不会在同一公开前缀下同时出现（判定一致性 + K5）；
  - "延期分支"没有单独建模：重验失败就回到旧程序，不延后再试。
- K5：检查 S 对迟到结果封闭，并在崩溃后重新判定。它不能单独替代穷举的异步构造（见 L1 后的说明）；
  本实现中由 K1 的 digest 比较保证提议契约就是内核按异步语义构造的契约。
- K6：目标按域的成功计数。成功环境是"每个执行立即成功、无崩溃"；其他环境下只保证收束。

### 5.5 简化清单

1. 公开事件只有回执、观察、完成三类；无回执操作的尝试不产生公开事件。
2. 披露是逐前缀的可能性语义，按世界比较；环境选择不算秘密。
3. 崩溃只在"接受"与"写切换记录"之间建模，每次运行至多一次。其余小步都是原子提交，崩溃对它们透明，
   响应丢失由 `Unknown` 结果表示。
4. 世界在一次运行内固定，没有运行中途出现的新事实（例如新文件）。
5. 切点只取顶层语句边界，且须能静态对齐，否则契约为 Unknown。较大运行中 29 个 Unknown 契约都属于这种情况，
   其中包括实际事件数固定、但静态计数保守地不认的循环。
6. 每次运行至多一次替换；多次替换只有纸面归纳。
7. 契约的关系部分是显式有限集合 S，不做符号化或压缩；C5 参数只记录取值范围。
8. 目标按域计数，没有按身份的目标项。
9. 新增 `Pin` 语句，表示两段式观察：先冻结，后释放。接收者字段只记录，不参与语义（单一读者）。
10. 默认接口取根中的全部域、操作、槽，以及切点前赋值的全部列表与句柄变量。
11. C6 只省略闭包外域的账本行与闭包外的槽；变量从不省略。
12. `ExecId` 是运行时计数器；"换身份"定义为 `ExecId` 重用。
13. Unknown 当作拒绝。
14. `FailedNoEffect` 退回额度（`ReleasedNoEffect`），`Unknown`（`Indeterminate`）永不退回。这对应框架 §6.3 提到的
    旧静态模式 NoEffect 语义；框架为新动态模式规定的"从 Reserved 起不自动退款"没有建模。
15. 弱化契约建模为"切换时只把契约与绑定携带的内容交给解释器"。
16. 关闭 K5，指构造不考虑异步返回、且不做封闭检查；关闭 K1，指提议携带另一切点的契约、且不做绑定检查。
17. 静态 K2 对分支内的赋值取并集：允许在分支之后读取只在一边赋值的变量，运行时读到旧值或空。这正是 C6 不省略变量的原因。
18. 循环上界 k ≤ 3；每个程序至多 4 个循环、8 个变量、3 个槽。

### 5.6 开放风险

- (c)(d) 的搜索每种只取第一个实质反例，说明"能找到"，不统计反例的多寡。
- 可靠性只检查了被接受的候选。被拒绝的候选中有多少其实安全，即检查的保守程度，没有统计。
- 字母表是手选的，候选只用变量 v6、v7。除 K2 的种类检查之外，候选变量与旧程序变量冲突的情形覆盖不全。
  C6 不省略变量的修正，是在推理中发现的，而不是由穷举发现的。
- K5 的封闭检查本身不足以证明覆盖（见 L1 后的说明）。将来若换成非穷举的符号构造，需要另外证明覆盖。
- T2 的多次替换与 T3 的复用只有纸面论证，代码没有实现。
