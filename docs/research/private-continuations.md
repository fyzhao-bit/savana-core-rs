# 证据驱动的私密任务延续：有界 Rust 原型规格

日期：2026-09-05。实现位置：`crates/savana-private-workflow`。
这是“原创性建议 1、2”的研究原型。它没有加入生产 V2 RPC、审批或 dispatch
路径，没有改动冻结内核，也没有替代 G1–G7。不能把它和已有生产路径的独立
验证结果拼接成一次并未进行的端到端验收。

## 1. 固定规则，动态对象

运行示例：用户认证一个结构化规则，允许查找某个账户/月份缺少发票的订单，
向经过认可的商家目录中的对应地址索票，每单最多一次。根规则不列出订单 ID。

`RootRule` 明确绑定 installation/task/principal/deployment、规则版本、账户、
月份、订单数据源、商家目录及固定版本、执行目标/凭据/工具身份、有效期、
事实最大年龄、订单/发现/披露上限，以及两个封闭枚举式程序名。
不能声明任意脚本、通配收件人或任意私密查询。规则不变不等于每步具体可用
动作集合不变：新事实可使更多实例就绪，但不能增加根规则中的授权关系。

`TrustPins` 由可信部署配置提供，issuer/orders/directory 三把验证密钥必须不同。
签名域按用途分离。消息先做大小限制和期望密钥验证，再按封闭规范 JSON 解码；
拒绝未知字段、重复字段、不规范编码、重复/无序对象及超限输入。

内核式 owner 先产生查询 nonce；订单与目录事实必须同时绑定根摘要、该 nonce、
期望数据源和时间窗口，不能把其他任务/查询的结果拿来当证据。新发现必须使用
不倒退的源快照版本；相同版本不能更改授权相关元数据。目录内容在整个任务中
不可替换，即使签名正确、版本号不变。历史元数据变化也不会替换已经建立的
订单实例；当前原型保守拒绝此类变化，不实现自动重授权。

### 哪些字段能成为依据

只有被配置为可信事实服务的结构化字段：订单 ID/版本/账户/月份/商家关联/
缺票标记，以及独立目录提供的商家/联系地址。账户和月份匹配、缺票为真且
目录关联存在，才产生实例。接纳绑定的是完整元组，不是可自由组合的字段集合。

`amount_minor` 和 `untrusted_note` 被解析并限制大小，但不参与选取、授权、
一致性判断、句柄生成或发出请求。尤其不能把备注里的邮箱替代目录地址。
即使备注包含在已签名消息中，它也不成为可信语义。签名不能弥补事实服务
本身撒谎；这些服务仍在明确的 TCB 内。

## 2. 状态、消费与实际请求

每个已发现订单保留一个稳定的任务内实例，不因新查询/新计划/重开 owner
重新生成。状态为 Ready、Reserved、Attempted、Retained、Done、Unknown 或
Unavailable。Reserved 起即永久消耗该订单的一次任务机会；没有返额或自动重试。
这是比生产任务引擎更窄的研究程序，不声称实现其所有重试选项。

事务顺序：

1. 原子提交已验证发现结果及其派生实例，然后才发布新视图。
2. 检查当前视图 epoch、实例和有效期，原子提交 Reserved，然后才返回 Pending。
3. 用 owner 的完整元组和固定模板构造现有 `BusinessRequestV2`。参数包含
   订单版本；正文只包含请求该订单发票的固定文本。调用既有 codec 比较 worker
   实际字节，并校验 transport 的目标/凭据身份。
4. 提交 Attempted，再调用可信 transport。不存在模型传入的 success 接口。
5. 先提交 transport 返回的原始响应，再调用现有 request-specific classifier。
   只有匹配请求的 `succeeded` 成为 Done；失败、未知、格式错误或丢回复均为 Unknown。
6. 提交终态后才发布模型可见状态。披露额度不足时仍持久化私有终态，但停止披露。

恢复时，Reserved 可继续同一次预留；Attempted 且没有保留响应只能变成 Unknown，
不重发；Retained 可以从保留的字节恢复分类，不重发。Done/Unknown 不会重新就绪。
撤销阻止之后的新预留和新 transport attempt，不撤回已经发生的外部效果。

可检查的安全义务：

- C1：每个实例都由已认证根规则和符合该根/查询/来源/版本的元数据产生。
- C2：同一实例的资源、版本、商家、目的地及固定载荷始终共同绑定。
- C3：每个任务内订单最多一次预留、最多一次受监控 transport 调用。
- C4：更新发现结果、重复事实、拒绝、重启和 Unknown 不能补充机会。
- C5：展示成功必须晚于匹配的真实响应保留和终态提交。
- C6：持久化不确定时当前 owner 不继续操作；认证重开不能遗忘已有预留/fence。

这里的“最多一次”不是商家内部业务 exactly-once。事实与执行间的 TOCTOU
依赖经过评审的服务执行 `order_version` 前置条件；本地检查无法证明任意远端
provider 的真实实现。`ProviderTransport` 是可信扩展接口，身份 getter 本身
不是网络认证；把一个不可信 transport 放进来会违反假设。

## 3. 规划器接口及允许泄漏

只有 `PlannerPort::exchange` 暴露给模型：Observe、Discover(epoch)、
RequestInvoice(epoch, handle)。不接受任意字段/谓词、地址、正文、工具名、
规则更新或完成断言。句柄由随机的任务私钥和序号生成，不哈希私密内容。
私有 RootRule、查询、证据摘要和实际请求不进入 planner reply 的可序列化类型。

视图是 schema、epoch、discovering/can_discover 和有序 opaque slots/status。
重复 Observe 返回相同的缓存，不产生新披露修订。内部 fence/响应保留没有改变
公开状态时，不改变公开 epoch。`max_disclosures` 限制不同视图修订，不限制重复
发送同一缓存的消息数。达到上限后统一 Unavailable；重启不重置上限。

本原型的允许泄漏函数 L 包括：

- 根程序类别和资源上限；已发现实例的数量、顺序和跨轮次相等关系；
- 根规则的匹配/就绪分支、事实新鲜性及来源/版本一致性校验的公开进展；
- 请求机会是否就绪、Pending/Done/Unknown/Unavailable 等粗状态；
- 发现阶段/是否还能发现、公开视图修订，以及统一拒绝。

这些是明确的泄漏，不写成“完全隐藏 shape”。例如订单数量不同，输出就可以
不同。对非法的金额阈值查询，无论金额是多少都返回同一拒绝；但不能用这个
事实声称时间、网络包长、调度或者外部 provider 行为也被隐藏。

### 关系式隐私目标与已有验证

比较两次运行：根程序/界限相同、对象可一致重命名、授权相关关系/新鲜性/
一致性事件/结果类别相同；允许金额、备注、订单/商家/联系地址的具体字节不同。
用同一随机盐耦合句柄生成，再让同一自适应规划器基于此前公开回复选择命令。
目标是两次运行的**序列化 planner transcript 相同**。这是相对 L 的目标，
不是“任意两个私有数据库看起来相同”。不同根意图间的等价性也尚未证明。

实现通过单一构造器控制输出字段，用独立枚举式投影限制内容，不暴露私密哈希、
细分错误或任意询问通道。26 项 Rust 测试包含三轮自适应双世界执行/恢复、
同版本隐藏字段更新，以及 48 组 eligibility/outcome/disclosure-bound 对照。
这些是有限见证；没有机械化的不干扰证明，也没有扩展旧 S1–S7 状态图来覆盖本模块。

## 4. 存储与隔离边界

`FileStore` 要求规范的私有 0700 目录，使用不跟随链接的 0600 普通文件和
独占文件锁。AES-256-GCM 保护状态；AAD 绑定命名空间、序号、前一状态摘要。
先同步新文件和目录，再推进外部 `RollbackProtectedStateAnchorV2`。
若 rename 后 anchor 更新失败，认证重开只接受恰好相邻且前驱匹配的状态。
更老状态、错误密钥/命名空间、状态删除和篡改被拒绝。

实际目录/文件操作是真实的，测试锚和示例锚是内存实现，不是硬件防回滚。
同账户攻击进程隔离、实际签名配置和生产网络中介都不由这个库自动提供。
PlannerPort 是 API/序列化边界，不是 Rust 进程内恶意代码的内存隔离。

## 5. 原创性及下一步不能跳过的工作

动态策略、能力、条件事实、不干扰和最小披露都已有研究。本文候选贡献是：
将动态对象实例化、明确披露面和持续消费义务放进一个可检查的有界实现。
Progent 的动态收缩/扩张、Fides 的受限检查和数据依赖任务、IGAC 的分步授权、
FORGE 的环境合同、CapAgent 的意图能力都必须公平比较，不能声称它们只做静态白名单。

示例控制器是确定性的，未调用真实 LLM。当前流程也可由工作流程序执行；
它验证边界，不证明 frontier model 的必要性或自主规划收益。需要进一步比较
真实规划器、纯本地/脚本基线、逐次审批与等价配置策略系统的任务完成率、
安全、披露和用户成本。反复查询正确但没有额外权限不是自动获得科研原创性。

生产集成仍需要经过认证的规则审批、事实服务 connector、真实网络 transport、
现行注册表/manifest/G1–G7/审批/dispatch 桥接和 OS 隔离部署。新 crate 的对象
不能直接作为旧 `VerifiedTaskMatchV2` 或生产 dispatch grant 使用。没有为接入
原型而更换现有生产内核、用户状态、Touch ID 或服务。
