# Savana 有界私密授权续行综合设计

创建日期：2026-09-05；最近修订：2026-09-06

状态：研究设计 v0.2；尚未实现、尚未证明、尚未证实原创性。

本轮只更新本设计，不改运行代码、其他设计、论文、部署、用户状态或 Git 提交。
本文中的模块、类型和接口均为拟议对象，不表示当前仓库已经提供这些能力。

## 1. 核心决定

在既有 [私密授权状态与可恢复续行提案](2026-09-05-private-authorization-continuations-design.md)
之上增加一个有界协议综合层：输入明确任务、固定权限、稳定消费、独立披露规则
与本地能力目录，输出一个可独立检查的续行协议，或有界无解证据，或 Unknown。

综合器回答的是“在这些条件下怎样继续”，不是“替用户决定增加什么权限”。
它不生成任意脚本、不代替现有授权器、不直接执行 MCP、不读取生产私密快照。

首版采用有限工作流骨架上的候选枚举与反例引导搜索，而非任意程序综合。
完整性只相对于给定骨架、候选语言、状态及任务边界，不声称覆盖所有合法算法。

v0.2 加入“残余授权契约 + 增量续行认证”作为明确的研究扩展（第 16–18 节）：
在同一根授权和任务内，对已执行部分建立可检查的残余契约，受控替换未完成的
续行片段，并复用未受影响的局部证明。该扩展不表示现在已允许生产策略热替换。
基础阶段仍固定策略；扩展须另过迁移、跨版本隐私和恢复验收门槛。

本提案补强前版第 13 节 C：隐私必须按每个公开交互前缀检查。未来获准的披露
不能为提前泄漏辩护。前版全文轨迹条件不再单独作为新综合器的充分验收条件。
其余稳定身份、审批、G1–G7、双 owner、固定观察与公开接收语义保持不变。

## 2. 研究问题及不作出的承诺

候选研究问题：资源不断出现，查询之间的资源重合关系属于秘密，历史执行与披露
消费不可撤销时，能否自动构造一个在更新和恢复后仍可合法继续的交互协议？

扩展研究问题：私密历史使后续合法机会发生变化时，什么条件允许 Agent 在同一
任务中更换续行计划，且证明、消费、执行不确定性与已披露知识可以安全继承？

需要同时满足：

1. 动态候选可以增长，但每个真实动作仍属于同一个认证根授权。
2. 同一资源换版本、路径、查询、handle 或计划，不获得新的消费机会。
3. 模型只依据此刻获准的观察行动，私密分支、余额和执行不确定性不默认公开。
4. 崩溃后延续同一个协议状态与账本，不把恢复当成全新运行。
5. 对明确支持的任务存在实际完成能力，而非仅返回“已接收”或全部拒绝。

不承诺任意自然语言任务、无限资源、无限故障下的任务完成、零时序侧信道、
对任意远端系统的 exactly-once、全局最少披露或必然获得论文强接受。
“私密”主要指不向不可信云端规划器披露；可信本地计算仍可读取获准事实。
这不是零知识证明方案，也不是在不信任本地内核时保证秘密不被读取。

## 3. 输入：独立规格而非模型自由文本

拟采用下列规范化对象，认证用户确认其语义；编译不能修改被确认的约束：

| 输入 | 必须包含 | 不允许用它替代什么 |
| --- | --- | --- |
| TaskSpec | 有限目标/义务、工作流骨架、允许的分支、私密终态 | 不把安全停止视为任务成功 |
| AuthoritySpec | 根规则、主体、来源字段用途、动作/目标、期限/撤销/审批 | 不因任务有价值就扩大授权 |
| ConsumptionSpec | 稳定任务/资源/消费域、总量/每资源上限、查询开销 | 不按计划或版本重新开户 |
| DisclosureSpec | 接收者、已批准函数、有限输出类型、观察槽、历史读权限 | 不把所有进展自动视为公开 |
| CapabilityProfile | 本地操作目录、必要外部能力、适配器和一致性语义 | 不默认本地可执行任意 LLM/代码 |
| EnvironmentSpec | 更新/响应/审批/故障假设、任务集合的边界 | 不把“外部永远正常”藏成前提 |
| ModelBounds | 历史资源、版本、节点、记忆、命令、观察及事件边界 | 不把求解器超时当成语义无解 |
| ReplacementSpec（扩展可选） | 固定的替换语言/片段边界、义务接口、控制点、提议次数与累计检查开销 | 不把允许重规划解释为允许重授权 |

ReplacementSpec 默认关闭；只有创建任务时明确认证该扩展的根才可启用。
既有固定模式不能因模型提交新计划而自动升级。允许范围不包括更改任务目标、
根权限、消费域、披露规则、能力/身份 profile、期限或总边界。

TaskSpec 的目标与允许私密结案原因分别定义，例如：

- Success：在指定已认证批次中，至少 k 个不同资源具有确认成功的动作结果。
- Settled：所有已接收义务均已成功或在私密 UI 中标为明确失败/Unknown/撤销。

Settled 不蕴含 Success。必须在实验中分别统计，不用“安全结案率”冒充完成率。
没有全集证明时不允许把有限发现写成“处理所有现在和未来出现的文件”。
要求 k 个成功时，必须说明合法资源、预算、审批及可确认响应为何足够。

CapabilityProfile 是必要输入：若本地能做一切且没有成本约束，“全部留在本地”
就是合法甚至最优的简单解。不得人为禁止这个解来制造创新；需要与同能力本地
基线比较。云端语义推理可作为任务能力，但其输出仍不具有授权事实的可信角色。

## 4. 可信边界与产物

工作分为四层：

| 层 | 职责 | 信任安排 |
| --- | --- | --- |
| 离线综合器 | 搜索候选、生成反例与证书 | 不可信；不读取真实私密数据 |
| 独立检查器 | 重建语义、检查候选全部行为及证书绑定 | 小型可信 Rust 组件 |
| 本地续行器 | 运行已检查的受限程序，保持私密状态 | 可信；在现有隔离边界内 |
| 现有内核/execd | 每次证据、授权、审批、消费、出站与真实执行 | 保留既有安全门 |

规格、有限语义、适配器抽象映射、解析器和序列化边界也属于 TCB；不能只列检查器。
综合器默认本机离线运行。规格本身也可能私密；未经独立许可不上传第三方求解服务。

拟定义三种综合结果：

- Realizable：附候选协议、精确边界和经独立检查通过的证明包。
- UnrealizableWithinBounds：该骨架与有限候选空间均已排除，并有可复核覆盖证据。
- Unknown：超时、检查资源不足、抽象不支持、反例无法具体化或其他未决情形。

发现输入格式错误可单独报告 InvalidSpec；这不是对任务可实现性的结论。
综合结果属于配置/研究管理面，不作为模型查询真实余额或资格的 API。

## 5. 有限资源与运行状态模型

首版从有限符号资源开始，不把真实对象 ID 或文件内容交给搜索器。

每个抽象状态记录：

| 分量 | 内容 |
| --- | --- |
| Public | 已接收公开命令、幂等回执、公开配额、发布槽 |
| Identity | 所有曾出现的逻辑身份、查询引用、别名关系、墓碑 |
| Evidence | 有限版本、资格/关系谓词、来源角色、有效性与一致切片 |
| PrivateControl | 程序节点、私密分支状态、循环游标、有限局部记忆 |
| Consumption | 各稳定域的单调 debit、每资源消费、未决执行 |
| Execution | 精确预约绑定、attempt fence、保留结果或 Unknown |
| Observation | 槽消费、固定输入、冻结输出、历史读许可状态 |
| Recovery | 两个 owner 的持久阶段、可信锚关系、有限故障状态 |

一个发现事件可以指向已存在身份，也可以在历史总数上限内引入新身份。
上限计算曾经出现的身份，而不是当前缓存条数；GC 不使身份槽或消费重新可用。
版本变化可以改变资格，但不能改变同一对象的消费归属。

沿用前版稳定键：

```text
TaskKey     = (InstallationLineageId, TaskLineageId)
ResourceKey = (LogicalSourceId, NamespaceId, CanonicalObjectId, Incarnation)
ChargeKey   = (TaskKey, ChargeDomainId, ResourceKey)
```

抽象 R0/R1 等编号只是证明中的名字，不能当成生产计费主键，也不能向云端公开。
来源适配器须在第一次消费前给出可信稳定身份映射；未知连续性私密暂停。
首版不支持事后任意合并两个已经分别消费的身份，也不以新 Incarnation 掩盖别名。
对象编号复用和连接器/签名密钥轮换必须服从适配器的固定身份契约。

首版直接枚举少量身份；身份对称性压缩留待证明后优化。任何置换必须一一对应，
保留整个相等图、消费记录、来源范围和公开名字，不能把所有 handle 合成一个。

## 6. 候选语言：综合什么，不综合什么

在预先审查的 ProtocolSketch 中只填写有限类型的选择位：

- DecisionPlacement：已有判断留在本地，或使用获准反馈由云端选择后继。
- ObservationChoice：从已批准的有限函数中选一个，或选择不释放。
- SuccessorChoice：从骨架已允许的有限后继中选取。
- MemoryLayout：在给定上限内保存必要的本地/公开控制状态。

具体 AST 复用前版 Discover、Select、ForEachBounded、If、Attempt、Await、
OfferObservation 的受限语义。无法公开的判断必须保持私密控制标签。

以下不是搜索变量：根授权、来源角色密钥、字段权限、总额度、稳定消费域、
审批要求、远端目标白名单、允许披露的函数集合及它们最早的发布时机。
不生成 arbitrary predicate、任意阈值探测、SQL、Python、Rust 回调或新的 release 规则。

候选不能随运行中的秘密改变公开程序目录。基础阶段初次选择产物只依赖已确认
规格和符号模型，不依赖当前真实余额或真实命中情况。扩展的符号替换证书也不
读取真实私密快照；具体迁移可行性由可信内核私密核验，且整个切换选择器须满足
第 17 节的跨版本关系式检查，不能公开具体迁移是否成功。

## 7. 首版算法：候选搜索 + 独立反例检查

建议先做显式小状态模型；SAT/SMT 只作为后续加速器，不是安全前提。

```text
canonicalize and validate specifications
define the finite, typed candidate space from the declared sketch
for each remaining candidate:
    check single-run authorization / consumption / recovery invariants
    check causal, two-run disclosure constraints
    check declared success and settlement obligations under their assumptions
    if every check completes successfully:
        return Realizable(candidate, independently checked artifact)
    if a concrete counterexample exists:
        exclude this candidate; optionally generalize only with checked justification
    otherwise:
        retain unresolved candidates; continue if useful
if every candidate has a checked exclusion:
    return UnrealizableWithinBounds(coverage and exclusion evidence)
return Unknown(unresolved obligations)
```

排除一个候选的反例不证明所有候选无解。未经验证的泛化不得跳过可能的合法候选。
候选数大或状态探索未完成就返回 Unknown，不设置默认“失败即不可实现”。

必须分开量化两类性质：

- Safety：对模型所有可提出的恶意命令序列、并发/重复以及模型内允许环境事件成立。
- Progress：对配合声明协议的参与者，在明确响应、审批、稳定窗口及故障前提下成立。

“配合”须是一份可检查的公开行为约束，而非“模型总会猜对私密事实”。
云端只能根据已有公开历史选择；两个公开历史相同的执行不能暗中给它不同建议。
不要用一个读取全部秘密的理想模型证明真实云端可以推进任务。

独立检查器还要检查前提非空且不循环：每个声称支持的初态，环境假设和参与者
协议均存在可延续的合法执行；相同实际公开历史下云端具有相同的选择约束。
不能通过禁止全部后继、保留未完成义务却陷入死锁，或将“任务已经成功”写成
环境假设来使完成证明空真。语义前提不可满足须报告规格问题，而不是 Realizable。

首版所有状态域和事件预算有限，优先检查全部可达状态与有限终点。
以后若加入无限空转或无限公平执行，再定义排名函数/公平性证明，不借用有界结果。

### 7.1 无解诊断

建议分为 AuthorityConflict、BudgetConflict、DisclosureConflict、CapabilityConflict
与 BoundConflict。对配置者给出约束、失败义务和可重放的反例。

预算冲突可能只需一个执行；隐私冲突常可展示两段历史；复杂控制冲突可能需要
反例树。完整结论来自候选空间覆盖证据，不承诺两个秘密状态能证明所有无解。

只有把允许本地分支也纳入所有候选后，才能说“该隐私限制阻止了任务完成”。
可以建议配置者重新审视目标或披露，但不自动扩权、重置任务或创建新预算。

## 8. 因果披露验证：逐前缀，而非只看最终输出

独立理想披露机器必须先定义。它不调用生产 projector，不把实际输出反写成规范。

首版采用确定性的有限投影与公开发行位置标识。检查目标为：在每个公开边界 t，
如果两个世界截至 t 的公开输入、公开控制事件以及合法披露前缀相同，则截至 t
的模型可见输出前缀必须相同。公开随机标识若存在，按公开发行位置耦合。

比较包含消息有无、错误、字段类型/长度/集合形状、ID 相等图、逻辑发布轮次、
历史记录及关闭语义。不要求两个世界实际处理相同文件或消耗相同业务额度。

例如：第 3 槽才允许披露一位结果，第 1 槽不能通过 Unavailable/Accepted 提前泄漏。
即使两个世界最终获准披露不同，也不能为第 1 槽不同的输出免责。

检查实现用双运行产品：各自保存完整私密状态，共享相同公开输入前缀；逐公开
边界展开私密内部步骤和独立披露机器，比较仍具相同合法披露前缀的运行对。
尚未发生的披露不用于提前拆分等价类。私密异常、无候选、余额不足都必须被覆盖。

未来若加入带概率机制，不把确定性双运行检查直接称为概率非干扰证明。
第一版不做差分隐私或“观察次数等于泄漏比特数”的承诺。

公开槽采用前版 total 发布语义；Strict 模式的槽不依赖私密结果。
Declared 模式覆盖材料缺失、无效、拒绝及未就绪输入；这些输出差异必须明确批准。
任何分支不能通过私密释放失败造成空槽，以绕过输出字段检查。

关系检查假定相同外生公开可用性/故障日程，允许两边不同内部私密步骤和故障切点。
不将由秘密决定的正常错误归为基础设施停机；不只比较相同私密指令位置的运行。
墙钟、流量、CPU/磁盘竞争以及获准目标串谋仍在首版范围外。

## 9. 独立证书检查及抽象到真实代码的义务

证明包至少绑定：

```text
root_spec_digest, task_goal_digest, disclosure_spec_digest
capability_and_adapter_profiles, environment_assumptions
semantic_version, abstraction_version, state_schema, model_bounds
sketch_catalog_digest, strategy_digest, executable_AST_digest
proof_format_version
```

扩展证明包还绑定 ReplacementSpec、旧/新片段、残余契约版本、接口/依赖图、
义务映射和迁移关系；这些绑定不能代替第 17 节的语义检查与当前状态核验。

只有摘要和签名不构成安全证明。检查器必须从规范化规格及固定语义重建所有
合法后继，或验证完整的后继覆盖证明。不能信任综合器提供的状态图是完整的；
否则删掉一个失败、更新或崩溃边就能获得假证书。

首版采用可独立重跑的显式检查。证书可携带可达集合、不变量和反例来加速，
但检查器仍确认初始状态覆盖、后继闭包、单运行性质和关系式输出性质。
Progress 检查还包含第 7 节的环境/合作策略可满足性、观察限制及防空真义务。
有界无解证据需独立枚举同一个候选空间并验证每项排除；求解器一个 UNSAT 字符串不够。
检查资源不足就不能激活该产物，也不能颁发无解结论。

还必须定义具体 Rust 状态到抽象状态的映射 alpha：

1. 认证激活和每个恢复初态均落在已验证的初态/续行状态集合内。
2. 每个真实可见步骤对应模型允许步骤；纯内部步骤最多对应受约束的停顿。
3. 具体输出的全部字段与模型观察一致，不能只检查业务 payload。
4. 私密资源、版本、一致性与故障抽象覆盖所有该部署可产生的相关分支。
5. 成功谓词对应真实保留响应，不对应模型自报或接收回执。
6. 双运行映射保留公开初态关系、已准披露前缀、共同输入及整个身份相等图；
   不能只有单运行模拟，就默认交互隐私已经传到具体实现。
   公开输入抽象、理想披露监控器、观察槽、随机标识发行位置和故障耦合，
   均不能依据秘密把本应比较的两段历史偷偷拆成不同等价类。
7. 完成能力还需进展对应：内部停顿有界，外部等待满足已声明响应假设；
   不能让实际实现永远停顿，却借抽象模型最终完成来证明真实任务会完成。

如果先使用过近似模型，安全通过可在正确模拟关系下支撑安全性；抽象反例未必
可实际发生。无解结论须有具体化或精确有限语义支撑，否则返回 Unknown。
不能把三资源模型通过说成 256 资源部署已证明；部署上限必须在证书覆盖内，
或另有参数化证明。差分测试是证据，不自动等于完整精化证明。

## 10. 实际运行：证书不能替代内核

新建认证任务时，把已验证协议与根契约、TaskLineage 和语义版本一同持久化。
首次恢复读取同一个协议和私密控制状态，不重新激活一个初始任务。
基础阶段禁止活跃任务热替换策略；事实更新是原协议内环境事件，不触发秘密驱动
的重新综合。只有第 16–18 节扩展验收通过且根已明确启用时，才允许受控片段替换。

每次真实动作仍按顺序满足：

1. 当前主体、根、部署、期限、撤销及程序入口有效。
2. 当前证据角色/字段用途、完整 read-set、稳定身份、快照一致性和执行前置条件有效。
3. 原有逐次审批及 G1–G7 检查完成，不以“已经认证过协议”为理由省略。
4. 同一 durable owner 原子检查并消费所有相关域，冻结精确动作和审批绑定。
5. 经过既有 dispatch 与 execd attempt fence；保留真实响应后再认定结果。
6. 模型输出经过 provenance/declassification/PlannerCall/handoff，不由 Python 直接投影。

证书失配、抽象超界或身份连续性无法确认时，不再生成新执行预约，并保持历史状态。
私密原因只对认证用户可见；已承诺的公开接收/观察语义按固定公开规则维持。
必须将这种超界停止纳入模型/监控器，不能事后添加新的模型可见错误。
原来已预约的动作仍按原 lease 与撤销语义处理，不能声称立即消除了所有在途效果。

## 11. 更新、执行与披露恢复

这些事件进入综合语义，不留作“实现时处理”的黑箱：

| 真实提交/事件 | 抽象转移 | 不得发生 |
| --- | --- | --- |
| 接收认证事实或版本更新 | UpdateEvidence | 清空身份、消费或披露历史 |
| T_exec 提交 | ReserveAndCharge | 把额度检查和精确预约分成可竞态两步 |
| execd attempt fence | AttemptStarted | 用新 nonce 重做未知尝试 |
| 真实响应持久保留 | RetainOutcome | 模型自报替代原响应 |
| T_pin | PinObservation | 同槽恢复时改用更新快照 |
| T_freeze | FreezeObservation | 同槽再次计费或冻结不同输出 |
| 历史重读 | ReadFrozen | 刷新私密状态后仍声称是同次观察 |
| reopen | Restore | 重置节点、游标、额度、墓碑或公开配额 |

沿用前版两类持久化流程：执行预约与出站；以及固定观察输入、冻结结果、读者许可。
不假设 provider、副作用、两个 owner 和浏览器之间存在一个全局原子事务。

Reserved 只有在 execd 认证日志证明未尝试且原条件仍有效时才可继续原预约。
尝试是否发生不明或效果已开始而响应未保留时进入 Unknown，不退款、不换节点重试。
ObservationPinned 恢复只计算原切片，所需依赖禁止 GC；冻结记录只能原字节重读。
当前读者权限与短 lease 仍需检查，读取撤销不伪装成瞬时回收远端已知信息。

持久化包括私密 pc/游标、身份等价类、所有消费、原请求、未决动作、固定观察输入、
冻结输出和公开幂等记录。两个 owner 的防回滚锚均须对账；缺失或落后不能初始化空状态。

安全在覆盖的崩溃切点都要成立；成功性必须区分两种环境：

- 结果可确认的环境：在规定窗口内达到真实 Success 的条件性目标。
- 允许永久 Unknown 的环境：保证不重试、不超支并可私密收束，不保证 Success。

若 TaskSpec 坚持任何故障后都必须确认成功，而执行 profile 可能永久 Unknown，
综合器应报告相应有界冲突；不能在证明时静默删掉这个故障分支。

## 12. 接口与 Rust 落点

新模式的模型面保留两个拟议逻辑接口，不向模型增加综合、查余额或逐资源探测接口：

```text
submit_step(task, program, public_args, command_id) -> PublicReceipt
observe(task, public_slot) -> FrozenPublicRecord
```

PublicReceipt 只确认提议已被可靠接收。公开格式/认证/配额错误与私密业务拒绝严格分离。
observe 不刷新事实、不推进任务、不生成新观察。Python/OpenClaw 仅封装公开调用。

新增管理工具为逻辑设计而非现有 SDK 承诺：

```text
synthesize(specifications, bounds) -> Realizable | UnrealizableWithinBounds | Unknown
verify(specifications, artifact)   -> VerifiedArtifact | Invalid | ResourceLimit
```

认证任务创建流程可附加 VerifiedArtifact；它不另开一个不经认证的 activate 接口。
原始反例、配置诊断和私密原因仅走配置者/用户管理面。

扩展不新增模型侧查询残余状态或迁移成功与否的接口。根可预登记一个固定的
提议入口，仍经 submit_step 提交有界、公开可描述的候选片段和 proposal_id。
PublicReceipt 只说明提议已接收。公开目录/入口不随私密迁移结果改变；证书、
活跃内部版本、残余状态、迁移拒绝原因与进展只进入获准私密管理面。

建议代码布局（尚未创建）：

| 拟议位置 | 职责 |
| --- | --- |
| savana-continuation-model | 有限值域、固定转移、理想披露、参考解释器；扩展残余契约与替换关系 |
| savana-continuation-synth | 候选/反例搜索；扩展片段证明搜索，不持有生产秘密 |
| savana-continuation-check | 独立证书、后继覆盖、单/双运行检查；扩展依赖闭包与跨版本验证 |
| policy-core/kerneld 既有 owner | 已检查 AST、动态证明、稳定消费、私密/公开状态；扩展原子迁移记录 |
| 既有 execd/vault/planner 链路 | 精确执行、响应保留、冻结观察与释放 |

现有代码的真实差距：

- [task_authorization.rs](../../../crates/savana-policy-core/src/v2/task_authorization.rs)
  的 candidate_domain 明确只来自完整静态签名合同。新增动态模式需独立证明分支，
  不把搜索结果伪造成 CompleteContractDomainV2。
- [task_state.rs](../../../crates/savana-policy-core/src/v2/task_state.rs) 已有条款计数与
  原子 prepare，但不等于本提案的稳定资源多域账本和综合控制状态。
- [durable owner](../../../crates/savana-policy-core/src/v2/durable.rs) 与
  [execd durable](../../../crates/savana-execd/src/durable.rs) 提供可复用的持久化基础；
  尚不能据此声称新增观察、续行和证书已集成。
- [原型 runtime](../../../crates/savana-private-workflow/src/runtime.rs) 同一订单版本或
  商家映射改变仍 Conflict；[原型 planner](../../../crates/savana-private-workflow/src/planner.rs)
  仍暴露 slots/can_discover/Done/Unknown，不满足新的默认披露语义。
- [planner authority](../../../crates/savana-kerneld/src/v2_agent_authority.rs) 的原释放链
  继续保留。若无法表达冻结历史依据，须审查新证明版本，不能绕过原门。

研究模型可用假 provider；生产不增加第二个可直接派发动作的数据库或 transport。
保留静态模式行为；新增模式默认关闭，混版拒绝而非降级。持久 schema 改变须防止
旧二进制忽略新字段写回；本设计不授权生产迁移或安装。

## 13. 一个贯穿案例及三个验收结果

文件任务：固定来源与归档目标，按 A/B/C 三个批准查询发现文件；业务预算 2、
每稳定资源一次。要求在有至少两个合法资源且结果可确认的条件下归档两个不同文件。
发现查询本身有独立有限预算与既有审批，不能视为免费或不受约束。

| 状态 | 世界 W0 | 世界 W1 |
| --- | --- | --- |
| A 命中 | F | F |
| B 命中 | F | G |
| A/B 后消费 | 1 | 2 |
| C 命中 | H | H |
| 最终执行 | F、H | F、G；H 因额度不足不执行 |

Strict 模式下，两边相同公开回执/槽，真实结果只给私密 UI。两边都可达“两个不同
文件成功”这个目标，但不是两边 C 都成功。综合器应找到本地去重/预算分支的候选。

候选若向模型返回 C 的真实成功/预算不足，会暴露 A/B 重合，双运行检查应产生反例。
若规格明确要求向模型报告 C 的真实结果而 DisclosureSpec 禁止该区别，严格模式
候选应被排除；允许本地判断也不能满足这个“必须告知云端”的冲突目标。
这个简单冲突用于诊断正确性，不作为原创性实验的全部证据。

版本与恢复变体：F 更新后仍是同一消费身份；崩溃在响应保留后只重建控制状态；
崩溃造成 Unknown 时保留消费、不重试，其 Success 指标如实失败或未决。
另设 DeclaredFeedback 任务，证明模型确实能依据已批准反馈选择后继，而非所有
任务都被提前写死成本地脚本。云端能力需求与本地能力边界须同基线一致。

## 14. 第一阶段范围与实施门槛

最小实验配置建议：3 个历史资源、每资源 2 个版本、2 次业务预算、3 个批准查询、
3 个公开槽、最多 1 次更新和 1 次崩溃、8 个程序节点、2 个有限控制记忆位。
初始 sketch 仅若干有限选择位，先确保完整枚举可执行；并非覆盖任意 8 节点程序。
上述配置是研究起点，不是已有支持或生产容量承诺。

单运行/双运行状态探索分别设实现资源上限，碰到上限一律 Unknown。
规模不通过则缩小或优化算法，不能删掉危险转移以取得成功结果。

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| S0 规格与失败案例 | TaskSpec、独立逐前缀披露、精确有限语义 | 正例能完成；错误回执/提前泄漏/身份重开户被捕获 |
| S1 搜索与检查器 | 有限 sketch 枚举、单/双运行检查、三态结果 | 能生成合法候选；删转移/伪证书/假无解均被拒绝 |
| S2 持久化模型 | 执行、观察和双 owner 故障切点 | 每切点保留消费/控制状态，Unknown 不重试 |
| S3 具体精化与 Rust 原型 | 状态映射、受控 provider、同一 owner 集成 | 真实转移/输出与模型对照，运行检查不被证书省略 |
| S4 通用性与收益 | 文件与邮件共核、真实模型 loop、强基线 | 同等权限/披露/本地能力下有可量化收益 |
| S5 论文主张审查 | 定理范围、限制、可复现 artifact、近邻比较 | 再决定研究主张，不能由功能清单推导强接受 |

基础阶段不做全局最小披露、无界综合、任意脚本、策略热迁移或新的密码学体系。
受控片段替换只按第 18 节扩展阶段推进，不降低 S0–S3 的验收要求。
“最少披露”若后续加入，先按可区分的历史定义偏序；可有多个不可比较的极小解。
布尔输出个数少不保证泄露更少，人工权重优化也不等于信息论最优。

## 15. 证明目标、实验与研究停止条件

证明目标均为待完成义务：

1. 接受产物可靠性：独立 checker 通过的协议在规定有限模型内满足其安全/进展规格。
2. 因果披露：每个公开前缀仅依赖已准公开输入与截至此时的独立合法披露。
3. 非再生消费：更新、别名、重规划请求、重连、恢复与 GC 不生成新的业务/披露机会。
4. 恢复保持：允许的持久化恢复保持协议、控制依赖、未决效果和冻结观察。
5. 相对完整性：在精确有限语义、固定 sketch 及穷尽检查下，存在候选就能找到；
   不包含超时/过近似未决，不推导无界可实现性。
6. 具体实现精化：生产路径与已检查模型之间的状态、输出和成功含义一致。

安全攻击包括提前披露、等价类/版本换身份、双消费、重复命令、审批反馈泄漏、
隐藏 Busy/空槽、私密循环次数影响公开轮次、Unknown 重试、同槽换快照与恢复失忆。
另测伪造 artifact 删除故障边、候选空间漏枚举、错误 alpha 映射与证书语义版本失配。

强基线必须获得相同稳定账本、本地分支、审批、持久化和披露限制：手写强组合、
普通 IFC 加共享账本、通用有界综合器使用同一个语义模型、纯本地固定工作流。
不能把 token 重发会回血的弱实现当作唯一对手，也不能人为剥夺基线本地能力。

测量真实 Success、Settled/Unknown、未经允许的可区分轨迹、额度违规、所需手写
可信逻辑和配置、额外披露/审批决策、搜索/检查时间、内存与运行开销。
三态结果单独统计，Unknown 不计作正确拒绝；相同任务/故障种子及模型版本可复现。

若普通综合器只是增加这些状态变量就同样解决任务，新算法原创性不足；应诚实
定位为模型/语义、精化或工程收益，不能声称发明了隐私综合。要继续冲高接受，
必须指出并解决一个实际的表达性、证明或规模障碍，而不是只提出新名称。
第一阶段若强基线已满足全部目标、没有自动化收益，应停止扩大生产实现范围。

## 16. 扩展一：残余授权契约

### 16.1 需要区分两种关系

模型看到的公开历史相同，不代表两个具体状态允许相同后续动作：

| 状态 | 已消费集合 | 剩余额度 | 下一步请求 F |
| --- | --- | --- | --- |
| S1 | {F} | 1 | 不得再次执行 |
| S2 | {G} | 1 | 在其他条件满足时可以执行 |

两者可具有相同公开历史，甚至相同余额，但不能把计费状态互换。
这不意味着同一个参数化协议不能覆盖两者：协议可以对集合 S 量化，由本地账本
检查 F 是否属于 S。复用的是带前置条件的证明，而不是把不同状态当成同一个状态。

扩展要明确区分公开观察等价、合法在线续行关系以及证书可复用关系。
仅声明最终合法 trace 集相同还不够：环境与控制器交替选择时，存在一条合法路径
不代表存在一个只看当前公开信息就能选择该路径的在线策略。

### 16.2 契约不是给云端的摘要或新令牌

拟定义 ResidualContract，为受限续行片段声明符号参数、单运行前置/后置条件、
成对状态关系、允许效果、未决义务及恢复闭包。具体值只由可信 Rust 组件通过
ResidualBinding 绑定到当前任务状态；不把私密快照交给不可信综合器。

| 契约内容 | 必须保持的含义 |
| --- | --- |
| 固定根、TaskKey、语义/身份 profile | 续行替换不成为新的授权任务 |
| 稳定身份及消费成员关系 | 同资源、别名、跨片段匹配共享原消费机会 |
| 多域 debit 与总资源上限 | 余额、查询次数、历史身份数、fuel 不重新初始化 |
| 已接收任务义务与私密 pc | 新片段继承尚未完成的工作，不丢弃义务来宣称完成 |
| ExecutionId 与原请求状态 | Reserved、可能已尝试、保留响应、Unknown 不按新节点重建 |
| 观察槽、固定切片与冻结记录 | 已 pin 的观察不换输入/函数，历史记录不冒充最新观察 |
| 已合法披露的前缀及接收者约束 | 后续证明从已有知识继续，而非从空历史开始 |
| 外部假设、进展义务与恢复关系 | 不加强环境假设、降低 Success 标准或省略故障边 |

需要说明哪些具体事实可以从证明结构中抽象掉，以及怎样构造这个结构。
不声称固定大小摘要可以替代无限历史。任意旧资源可重现时，精确消费成员关系
或可信成员查询必须存在；真实账本、墓碑与固定观察依赖不因证明压缩而删除。

### 16.3 三类必要性反例

1. **只有余额**：S1/S2 余额相同，但同一未来资源的消费许可不同。
2. **只有消费集合**：都已预约 F；一边经认证证明尚未尝试，另一边可能已产生
   效果而结果未知。前者在原条件下可继续原预约，后者不能以无响应为由重发。
3. **只有披露次数**：都消费了一个观察槽，但固定切片或函数绑定不同；恢复后
   不能都改用“最新快照”，也不能让替换后的 projector 重新解释原槽。

反例是规格和消融测试，不单独作为创新成果。要证明更弱契约在何种语言内不足，
还要证明拟议契约对声明的续行操作足够；不能仅列出字段然后自称最小充分摘要。

### 16.4 局部证明接口与依赖

首版扩展限制在第 6 节 AST、固定事实用途、稳定身份等值比较和单调消费操作内。
可替换的片段及其义务接口在根的 ReplacementSpec 中定义；不能增加查询模板、
目标、来源或任意操作。新计划可选择允许后继或调整未执行步骤，不改变任务目的。

片段证明缓存分两部分：

- 静态证明：语义版本、AST、根规则、契约公式和接口不变时可检查复用。
- 动态适用条件：当前资格、身份映射、审批、消费、未决结果和切片等，须在迁移
  提交时验证；静态证明仍有效不代表某个具体动作当前就允许执行。

检查器计算并验证依赖图，覆盖数据、控制、异常、集合成员/顺序以及关系式观察。
不能信任候选自己声明“没有依赖某字段”。两个片段即使处理不同文件，只要共享
总额度、去重域、观察槽或完成目标，也不是自动独立；影响须传播到依赖闭包。

## 17. 扩展二：增量续行认证与原子替换

### 17.1 相对基础方案的实质新增

基础证书已覆盖的普通事实更新本来就无需重新综合，不将“更新后继续”重新命名
为本扩展贡献。扩展研究局部证明组合，以及根允许的续行片段发生变化时，怎样
继承历史并只重验受影响的部分。固定策略模式与受控替换模式分别验收。

拟议增量过程：

1. 对旧/新片段及 ResidualContract 验证规范化绑定，计算改变的依赖闭包。
2. 复核未改变的局部证明及其边界条件，重验改变片段与所有受影响的共享关系。
3. 构造旧控制点、已接收命令和待完成义务到新片段的映射；映射不得丢弃、重复
   或改变原义务。原 ExecutionId/ObservationSlot 不随节点改名重新生成。
4. 检查完整切换选择器的跨版本隐私与进展，不只检查新片段自身。
5. 输出 VerifiedReplacement、RejectedWithWitness 或 Unknown；后两者不切换。

这些结果属于可信管理面。一个替换被拒绝不代表整个任务在有界范围内无解；
增量条件不足时可回退完整验证，资源不足仍为 Unknown，不能擅自放行。
无关证明可以复用的条件必须被检查，不能仅比较两个版本号或 payload 哈希。

### 17.2 跨版本隐私是单独的证明义务

旧、新协议各自安全，不足以证明按私密条件选择其中一个仍然安全。
同一公开提议下，世界一可能成功迁移，世界二因私密余额或义务不同仍用旧片段。
必须比较“新/旧”“旧/新”及成功/延期/拒绝等组合，而非只做“新/新”的双运行。

检查从已有合法披露前缀和公开命令历史开始；迁移结果、内部版本、证书标识、
公开入口是否可用、后续错误、公开槽和未来反馈均不得额外区分这些世界。
隐藏迁移当次返回值不够。若两边未来都需云端配合，合作策略也须对相同实际
公开历史具有相同选择约束，不能暗中把“是否已切换”告诉证明中的理想云端。

首版扩展不增加披露函数或更改发布日程；旧观察义务必须延续。
不能用“新版本允许透露了”追认旧版本尚未获准的消息，也不重置已获知历史。

### 17.3 提议、验证与提交

1. **公开接收**：按原任务固定入口、全局命令配额和幂等键接收提议，只返回
   接收回执。提议数、累计编译/核验开销与内存各有固定上界；重复请求不创建
   新迁移、返还资源或无限触发验证，私密拒绝不能改变公开配额/目录。
2. **离线检查**：综合器处理符号契约和公开可描述的片段；独立 checker 验证
   替换证明及后继覆盖，不接收当前真实余额、身份集合或秘密值。
3. **私密绑定**：现有 owner 在声明控制点读取残余状态及内部状态序号，验证
   动态前置条件、完整义务映射与当前根/撤销状态。控制点需所有相关解释器局部
   状态可持久表示；不等于外部执行已全部结束，也不把 Unknown 误当为空任务。
4. **原子提交 T_replace**：同一 kerneld owner 比较旧片段、状态序号及完整相关
   依赖仍匹配；同一事务停止旧控制流产生新预约，安装新片段/控制映射，保存
   旧义务引用、不可变迁移记录与幂等结果。并发 prepare/撤销/更新使条件失配时，
   只私密重验、延期或拒绝；重验消耗原任务的累计检查预算，不无限重试。
5. **锚定后生效**：状态和可信锚确认前，新片段不得产生新行为。只有确认
   T_replace 未提交时才可继续原片段；提交后以同一迁移记录恢复，不能因回复
   丢失再切换或重新绑定一次。提交或锚定结果不确定时，停止该任务的新预约，
   按既有 durable owner 恢复协议判定有效状态；不得当作未提交恢复旧控制流，
   也不得凭内存状态激活新片段。旧在途预约仍按第 17.4 节处理。

迁移记录至少保存稳定 TaskKey、提议幂等绑定、旧/新内部控制修订、产物/证书摘要、
残余契约与状态绑定、义务映射、依赖验证依据及提交顺序。内部控制修订只防止
过时解释器生成新预约，不替代根授权/撤销版本，也不自动作废已签发的精确预约。
记录、旧片段中仍被引用的恢复/投影语义及相关对象必须按依赖保留。

替换继承原 TaskKey、根、目标、消费域、历史身份数、观察槽、公开接收配额、
累计 fuel、查询/提议/检查次数、期限和撤销状态。允许映射局部循环游标，但
不能得到新的全局循环机会。创建新的工作流实例 ID 不产生新的业务消费域。
与目标不相容的已接收命令须在切换前按原合同处理，或拒绝迁移，不能直接丢弃。

### 17.4 旧执行与观察义务独立于新控制流

切换不修改 execd 的真实日志，不制造跨 owner 原子事务。旧 Reserved、attempt
fence、保留响应和 Unknown 按稳定 ExecutionId 保持；旧许可仍绑定原精确请求、
审批、lease 与撤销语义，不因新片段延长、克隆或重绑。

旧控制流不得再发起新预约，但已经预约的动作仍可按原规则继续。execd 在验证与
切换之间可能推进尝试/结果状态；迁移证明需覆盖这些允许的异步后继，或在对应
profile 无法覆盖时延期切换，不能凭 kerneld 的旧快照认定执行器没有尝试。
迟到响应只交给匹配原请求的唯一持久义务；新片段只能依证明映射消费该结果，
不得重复计费、误投同名新节点或重新触发已经消费的发布。

Unknown 保持不可重试，直到按原协议取得可认证结果才能细化分类；新计划的
逻辑意图不能作为“原来没执行”的证据。真实 Success 与安全 Settled 继续分别统计。

已 pin 观察保留原槽、切片、函数、接收者及释放依据，由原确定性语义继续冻结；
已冻结记录保留原字节。新片段继承未完成的发布义务，不用新函数重新解释旧槽，
不取消已承诺公开槽。旧读者许可仍按原短 lease 和当前读权规则处理。

恢复依据已锚定的 T_replace 记录确定活跃控制版本及完整义务集合，然后按既有
双 owner 规则对账。不能因为旧程序不活跃，就推断旧动作没有执行。任一必要
记录/锚缺失、回滚或矛盾，停止新行为并进入可信恢复流程，不初始化空账本。

## 18. 扩展的证明目标与验收门槛

### 18.1 核心定理目标

在固定的受限操作语言、根契约、模型边界和非空环境假设下，若替换证明经独立
检查、具体残余状态满足其前置条件且 T_replace 原子提交，则组合后的在线协议：

- 保持原授权边界、稳定消费、已接收义务和既有执行/观察历史；
- 保持包含迁移成功/失败选择器的逐前缀披露性质；
- 在原有响应、审批和故障前提下保留所声明的成功/收束能力；
- 在允许的提交和双 owner 故障切点恢复后，仍满足上述约束。

可采用保持观察与控制/环境选择结构的交替模拟，或证明等效强度的在线策略
保持性质。只证明单运行状态模拟、哈希相同或最终 trace 集相同均不够。
先证明一个可靠的单向复用规则，不承诺所有合法计划替换都能识别；扩大覆盖
需要另给完整性论证。旧证明的依赖不成立时，其复用结论不成立。

残余契约的构造法、关系式组合条件和迁移协议均需独立给出；本段是待证明目标，
不是借用“可组合”一词便自动成立的定理。

### 18.2 实施阶段

| 阶段 | 交付 | 门槛 |
| --- | --- | --- |
| R0 必要性 | 第 16.3 节三类反例、精确残余语义与初始构造法 | 不是只把账本字段重新打包 |
| R1 证明复用 | 局部契约、检查器计算的依赖闭包、完整验证对照 | 可复用结论可靠，保守拒绝/Unknown 单列 |
| R2 受控替换 | 根可选模式、跨版本双运行、T_replace 与恢复模型 | 私密成功/失败组合、全部迁移故障切点通过 |
| R3 Rust 与通用性 | 原 owner/execd 集成、文件和邮件同规则 | 具体执行/披露与模型一致，不省略原有门 |
| R4 原创性审查 | 强缓存/参数化证明/全局验证基线、消融与规模结果 | 存在可解释的表达性或验证成本/开发负担收益 |

R0/R1 可随 S0–S2 的小模型研究推进；R2 以前不启用真实替换，R3 还需完成基础
S3 的具体精化。初始增量测试在原三资源、两版本、两次额度、一次故障边界内，
取两个观察槽的子配置，并最多一次片段替换；之后逐项扩大，不外推无界保证。

至少覆盖：验证与提交之间的消费/撤销/事实更新；同任务重复/并发替换；新节点
编号绕过旧消费；替换重置 fuel 或公开配额；旧 permit 并发派发和迟到响应；
Unknown 重试；pinned 观察换 projector；迁移提交与 execd 不同阶段的崩溃；
只恢复活跃版本而漏掉披露前缀；两个私密世界迁移结果不同但未来公开行为泄漏。

对同一候选与状态，增量 Accepted 必须被完整验证接受；若为保守规则，增量拒绝
而完整验证通过的情况属于覆盖损失，不计为正确无解。声明相对完整的子语言内
再要求精确一致。删掉身份、尝试状态或观察绑定的消融版本应产生对应反例。

强基线拥有同样的稳定账本、本地分支、持久化、审批、参数化证明和缓存机制。
基础证书已经覆盖的事实更新不强迫基线重跑全局验证；分别测量初次证明、真实
片段变化、兼容更新及故障恢复。比较受影响证明量、检查时间/内存、支持规模、
手写可信逻辑、Success/Settled/Unknown 与实际审批/披露，不虚构基线负担。

若抽象仅是状态重包装，普通强缓存达到同样效果，或有效性只能靠禁止有用的
替换/反馈获得，则停止把它当作主创新。原创性“4 分”只是研究讨论目标；不能
由完成该清单直接推导评分、首次性或录用。

## 19. 研究依据与新旧工作的界限

- [Swift](https://www.cs.cornell.edu/jif/swift/) 已通过信息流策略自动划分代码位置；
  自动决定本地/远端位置本身不作为新贡献。
- [Combinatorial Sketching for Finite Programs](https://research.ibm.com/publications/combinatorial-sketching-for-finite-programs)
  已研究有限程序骨架综合；本方案采用的反例引导路线属于既有方法基础。
- [Optimal Synthesis of Opacity-Enforcing Supervisors](https://arxiv.org/abs/2102.01402)
  已研究隐私约束下的控制器综合；不能将一般隐私控制问题宣称为首次提出。
- [Compositional Synthesis of Opacity-Preserving Finite Abstractions](https://arxiv.org/abs/2004.00131)
  已研究保持隐私性质的可组合有限抽象；“可组合抽象”本身不是本扩展的新发现。
- [Compositionality and Observational Refinement for Linearizability with Crashes](https://flint.cs.yale.edu/certikos/publications/crashlin.html)
  已研究全系统崩溃下的可组合性与观察精化；不能把“跨恢复的证明”整体据为新贡献。
- 现代 Agent 授权/信息流/持久化近邻及强组合要求见前版第 16 节，仍需逐项核对
  完整论文和当前实现。本轮不是完整系统性文献综述。
- [USENIX Security 2027 CFP](https://www.usenix.org/conference/usenixsecurity27/call-for-papers)
  要求原创性、相关性、科学严谨性、正确性与清晰度。本文是待验证研究路线，
  不是官方五分制评分、已获定理、现有实验结果或录用保证。

下一项建议工作是 S0/S1 小模型和独立检查器，并同步验证 R0 的残余契约反例与
必要性；以此决定是否推进增量认证。代码实施、论文改动、安装迁移、提交和
推送均不在本次设计交付中。
