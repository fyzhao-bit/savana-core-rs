## 已有的两条不同路径

1. `official_agentdojo.py`：官方任务、真实模型回复、官方工具和官方 oracle；
   `ToolsExecutor` 直接执行官方 runtime，是无防护基线。
2. `agentdojo_provider.py` + `v04_fused_dispatch_tests.rs`：真实 Rust 授权和
   执行许可后调用模拟邮箱，但授权根、有限计划和模型输入来自合成测试夹具。
   这是原生组件互通，不是官方任务上的受测 agent。

不能把第一条的成绩与第二条的内核日志拼成一轮“防护实验”。

## 正式防护路径的剩余缺口

| 缺口 | 当前源码证据 | 必须完成的行为 |
|---|---|---|
| 官方任务/工具适配 | 新增 `fused_task_compiler.rs` 支持从当前根与签名工具注册表编译有限骨架，已有原子签名管理入口；尚无正式任务适配 | 从干净任务与预先批准策略建立根、注册真实工具 schema/语义，把模型提议交内核检查；不能使用隐藏答案或攻击目标生成权限 |
| 生产模型通信的部署 | 新增 Unix mTLS worker、签名 bootstrap 配置装载、Python endpoint 和 DeepSeek callback；无配置时仍禁用 | 安装受签名配置、独立证书与服务端，进行真实私密任务端到端验收；新代码尚未部署 |
| 结果接收与重连 | 工具结果独立发布条款、原生审批/G3/G7、vault/execd 提交和发布恢复已有实现；旧接口保持原始输入限制 | 接通生产用户接收端与新认证重连，完成多服务验收；不得将测试接收端当作生产身份校验 |

已有 `FusedModelTransportV04` trait、Python 会话封装或官方 runtime 不能替代这些行为。
尤其是把任意工具返回包装成 `PlannerEnvelope` 并不自动获得披露授权。

## 验收顺序

1. 固定一个同时有合法多步读取和真实写操作的官方任务小集合，事先定义根策略。
2. 逐个注册其原生工具；执行必须走内核 → 密封许可 → 执行器 → 模拟环境，
   禁止 Python 的直接执行回退。根策略不得依赖 clean/attack 分组标签。
3. 原始结果回内核私密库，只有经批准的视图进入下一次模型请求；最终结果单独批准。
4. 每次效果与披露关联 task/run、根版本、调用摘要、许可、执行结果及观察摘要。
   对越权、许可重放、迟到结果及恢复逐项验证；基础设施失败记 Unknown。
5. 用同任务清单、同模型配置做正常/攻击配对实验，官方 oracle 复核实际模拟状态。
   再扩展任务范围，不把小集合称为全量成绩。
